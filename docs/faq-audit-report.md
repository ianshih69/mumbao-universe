## 主要風險

1. 所有 FAQ 目前都為 `approved` 且 `is_active=true`，strict mode 必須靠程式層再次篩選，不能假設資料永遠乾淨。
2. 500 題全部為 `answer_mode=direct`，其中價格、退款、付款、發票、個資、外部服務與行程題建議改為 `collect_info` 或 `ask_human`。
3. 多題共用完全相同答案，容易讓不同問題拿到泛用、不貼題的正式回答。
4. 多筆關鍵字過度寬泛，例如「訂房」「入住」「寵物」「早餐」「停車」「費用」，不可單靠這些詞判定 high confidence。
5. `guesthouse-rules.md` 仍含房價、押金、訪客費、入住時間、早餐與寵物規定等住宿事實；strict mode 不應把整份 markdown 當成可自由回答背景。

## 稽核規則覆蓋

| 檢查項目 | 結果 |
|---|---|
| 問題與答案主題可能不一致 | 有，代表例：`faq-110`, `faq-112`, `faq-114`, `faq-493` |
| 關鍵字過度寬泛 | 有，常見於「訂房」「入住」「寵物」「早餐」「停車」 |
| 關鍵字疑似被截斷 | 有，代表例：`faq-493` |

| answer_mode 全部都是 direct | 是，500/500 |
| 所有題目全部 approved 的風險 | 是，500/500 |
| FAQ 與 guesthouse-rules.md 的數字或規則衝突 | 有待人工確認，代表例：早餐價格、入住時間 |
| 同義重複題 | 有，付款、停車、行程、兒童備品等群組明顯重複 |
| 問題有明確數字要求但答案沒有回答 | 有，價格/費用類多筆 |
| 問題問設備是否存在，答案只說依公告 | 有，需人工拆成可回答與需確認 |
| 價格、退款、發票、個資或法律題仍為 direct | 有，付款/發票/退款群組需優先複核 |

## 建議處理順序

1. 先處理主題錯配題：`faq-110`, `faq-112`, `faq-114`, `faq-493`。
2. 再處理和 `guesthouse-rules.md` 數字可能衝突的題：`faq-080`, `faq-205`。
3. 將價格、退款、發票、押金、訂金、個資相關題改為 `collect_info` 或 `ask_human`。
4. 將寬泛 keyword 拆成完整問句 aliases，保留 keywords 為短詞但不要讓單一寬泛詞觸發 high confidence。
5. 把 `guesthouse-rules.md` 中仍需正式回答的事實拆入 `faq-master.csv`，人工審核後再輸出到 `faq-items.json`。
